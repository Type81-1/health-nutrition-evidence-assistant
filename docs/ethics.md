# 伦理准则与免责声明

> 最后更新：2026-08-11

## 一、服务定位

**食证（Health Nutrition Evidence Assistant）** 是一款面向普通消费者的健康营养科普工具。系统基于公开发表的生物医学文献（PubMed / Europe PMC）和本地预索引的证据库，通过大语言模型生成通俗化的营养知识回答。

本工具 **不是** 医疗器械、不是在线问诊平台、不是个性化营养处方系统。

---

## 二、核心伦理原则

### 2.1 循证优先

所有回答必须基于可追溯的公开研究证据。每句结论标注 [E编号] 引用锚点，读者可据此核查原始文献。无证据支撑时，系统明确声明"当前证据不足以得出结论"，不凭空编造。

### 2.2 不替代专业医疗

系统输出的任何内容 **不能替代** 医生、注册营养师或其他持证医疗专业人员的诊断、治疗或个体化建议。用户做出任何健康相关决策前，应咨询专业医疗人员，尤其存在以下情况时：

- 已确诊的慢性疾病（糖尿病、高血压、肾病、心血管疾病等）
- 正在服用的处方药物（降压药、降脂药、降糖药、抗凝药等）
- 孕期、备孕期或哺乳期
- 儿童、老年人等特殊人群
- 食物过敏或不耐受

### 2.3 安全过滤

系统内置多层级安全审查机制，对以下类型请求 **不予作答**：

| 拦截类型 | 示例 |
|----------|------|
| 寻求未经科学验证的民间偏方 | "有什么治糖尿病的偏方？" |
| 要求替代正规医疗 | "不吃降压药，靠饮食能行吗？" |
| 要求疾病诊断 | "我这个症状是什么病？" |
| 要求用药建议 | "该吃什么药？" |
| 涉及已知危险药材/食物 | 何首乌、马兜铃、生吃泥鳅等 |
| 伪科学主张 | 酸碱体质、排毒餐、辟谷疗法 |
| 极端饮食行为 | 长期断食/绝食疗法 |

拦截时系统返回明确声明："基于安全与伦理准则，[具体原因]。"

### 2.4 证据局限性

- **知识库覆盖**：本地预索引文献来自 PubMed 精选检索（15 个健康维度），共 500+ 篇，存在主题覆盖不均的可能性。实时检索依赖 PubMed / Europe PMC 的可用性。
- **证据等级差异**：系统标注每条证据的类型（系统综述/Meta分析 > 临床指南 > 随机对照试验 > 观察性研究），用户应理解不同等级证据的证明力差异。
- **时效性**：生物医学知识快速演进，今日的共识可能被明日的证据推翻。系统优先展示近 5 年文献，但也包含历史里程碑研究。
- **语言偏差**：目前知识库以英文文献为主，中文查询需经 LLM 翻译为英文检索词，翻译质量可能影响检索效果。

### 2.5 AI 生成声明

系统使用大语言模型（DeepSeek）生成回答。尽管有严格的证据约束和引用校验机制，AI 生成内容仍可能出现：

- 对原始研究的过度简化或错误概括
- 对证据质量的判断偏差
- 特殊场景下未充分考虑个体差异

用户应始终保持批判性思维，不以 AI 输出为唯一决策依据。

## 三、数据与隐私

### 3.1 数据收集

系统在用户主动提交查询时，记录以下信息用于技术改进：

- 查询文本（脱敏后）
- 检索数据源与结果数量
- LLM 调用状态与引用数量
- 安全过滤触发情况
- 请求处理耗时

### 3.2 不收集的信息

系统 **不要求** 用户注册、登录，**不收集** 姓名、联系方式、地理位置、设备指纹等个人身份信息。会话 ID 为本地生成的随机字符串，无用户画像含义。

### 3.3 数据存储

查询日志以 JSONL 格式存储于服务器本地，自动轮转（单文件上限 10MB）。不传输至第三方服务（除 LLM API 调用的技术必需内容外）。

## 四、责任边界

1. **用户责任**：用户应自行判断 AI 生成信息的适用性。因依赖本工具输出而产生或未产生的任何行动及其后果，由用户自行承担。

2. **开发者责任**：开发团队持续改进检索质量、安全过滤机制和证据覆盖度，但不对以下情况承担责任：
   - 第三方 API（PubMed、Europe PMC、DeepSeek）的可用性或输出准确度
   - 用户忽视免责声明而做出的健康决策
   - 不可预见的系统行为或错误

3. **紧急情况**：如用户处于医疗紧急状态，应立即拨打急救电话（中国大陆 120），而非使用本工具。
